# Передача проекта QR Отзывы

Документ для разработчика, который продолжает работу. Сначала прочитайте его, потом
[`CLAUDE.md`](../CLAUDE.md): там архитектура, все согласованные решения и правила кода.
Claude Code подхватит `CLAUDE.md` автоматически.

## 1. Что за продукт

B2B-сервис сбора отзывов через QR-коды. Бизнес (первая ниша — салоны красоты и
барбершопы) размещает QR на стойке, визитке мастера, столе или в Telegram. Клиент
сканирует код, ставит оценку 1–5, отмечает категории, пишет текст и по желанию
оставляет телефон за бонус. Отзыв привязывается к компании, филиалу, точке и мастеру,
который был привязан к точке в этот момент.

Владелец салона видит статистику в кабинете и получает в Telegram уведомления
о негативных отзывах. Управляющий видит только свой филиал, мастер — только свою
статистику.

Ядро не зависит от ниши: всё нишевое (категории, «мастер», тексты формы) лежит
в YAML-шаблонах `backend/app/niches/`. Проект готовится для реальных клиентов, поэтому
важны изоляция данных компаний, 152-ФЗ и 38-ФЗ, тесты и понятная документация.

## 3. Требования к оставшимся этапам

### Этап 6 — воркер, бот, алерты

Из ТЗ и поправок владельца:

1. **Уведомления о негативе.** Если оценка ≤ `negative_threshold` компании (по умолчанию 3),
   после сохранения отзыва в arq ставится задача. Она отправляет сообщение всем
   пользователям компании с ролью `owner` и `manager` **того филиала, где оставлен отзыв**,
   у которых привязан Telegram.
   - Хук ставится в `services/review_service.submit_review` после commit. Сервис только
     ставит задачу и сам Telegram не вызывает.
   - Подозрительные отзывы тоже уведомляют: в сообщении пометка ⚠️ и причина антифрода
     (решено владельцем).
   - Текст алерта: оценка, филиал, точка, мастер, категории, текст отзыва, ссылка в кабинет.
     ПД клиента (имя/телефон) в Telegram **не отправлять**: шаг контакта идёт после отзыва,
     и сам текст отзыва — уже достаточно.
2. **`NotificationChannel`** — интерфейс в `services/notifications.py` (например,
   `async def send(recipient, message) -> None` плюс выбор адреса получателя).
   `TelegramChannel` — первая реализация, вызывает Bot API напрямую через `httpx`, без
   aiogram в бэкенде. Воркер работает **только через интерфейс**, чтобы потом добавить
   email, MAX или SMS без переделки воркера. Поле `users.telegram_chat_id` остаётся.
3. **Привязка Telegram:**
   - кабинет вызывает `POST /api/v1/telegram/link-code`, создаётся одноразовый код
     (в БД — хэш, таблица `telegram_link_codes`, TTL `TELEGRAM_LINK_CODE_TTL_MINUTES`);
   - в ответе deep link `https://t.me/<TELEGRAM_BOT_USERNAME>?start=<код>`;
   - бот на `/start <код>` вызывает внутренний эндпоинт бэкенда `/internal/telegram/link`
     с заголовком-секретом `INTERNAL_API_SECRET`; nginx отдаёт `/internal/` наружу как 404;
   - бэкенд записывает `chat_id` пользователю и гасит код;
   - нужны также отвязка (`DELETE /api/v1/telegram/link`) и ответ бота на неверный или
     просроченный код. Все тексты бота на русском.
4. **Бот** (`bot/`) только привязывает аккаунты. Без токена он уже сейчас не падает,
   а ждёт (`bot/bot/main.py`).
5. **ML-заглушка:** папка `ml/` с README-планом (аспекты, тренды, дайджест, датасет,
   сервис инференса) и пустая задача-заглушка в воркере (`analyze_review_stub`).
6. **Тесты:** алерт уходит owner и manager нужного филиала с привязанным Telegram и не уходит
   остальным; порог берётся из настроек компании; Telegram замокан через `httpx.MockTransport`;
   привязка кодом, просроченный и повторный код; изоляция компаний.
7. **Повторы:** ошибки Telegram (429 или 5xx) повторяются силами arq (`max_tries`). Если
   пользователь заблокировал бота (403), это логируется без ПД, и задача не падает бесконечно.

### Этап 7 — API статистики

- Разрезы: компания, филиал, сотрудник, QR-точка, тип размещения.
- Метрики: количество отзывов, средняя оценка, распределение 1–5, динамика по дням / неделям /
  месяцам, разбивка по категориям (по `code` и названию), последние отзывы с фильтрами
  (период, филиал, сотрудник, точка, оценка, категория, только с текстом), пагинация.
- Фильтр «исключить подозрительные» (`is_suspicious`).
- **Группировка по дням / неделям / месяцам — в часовом поясе компании** через
  `AT TIME ZONE` (`OrgSettings.timezone`, по умолчанию `Europe/Moscow`). **Обязательные тесты:**
  - отзыв в **00:30 МСК** должен попасть в «сегодня» по МСК. В UTC это 21:30 предыдущего дня,
    так что тест ловит ошибочную группировку по UTC;
  - отзыв в **23:30 МСК** должен остаться в том же дне. Тест ловит двойное преобразование
    часового пояса.
- Считать SQL-агрегациями с существующими индексами, без предагрегации.
- Права через `scope.review_filters()`: owner — всё, manager — свой филиал, employee — только
  свои отзывы. Тесты прав и изоляции компаний обязательны.
- Контакты клиентов в ленте (решено владельцем): manager видит их только в отзывах своего
  филиала, если `OrgSettings.managers_see_contacts` (по умолчанию `true`); employee не видит
  никогда. Поиск по телефону и отзыв согласия остаются только у владельца.

### Этап 8 — дашборд (UI на русском)

- **Страницы:** логин, регистрация, принятие приглашения, главная (сводка и графики), филиалы,
  сотрудники (таблица и карточка с графиком рейтинга), QR-коды (создание, скачивание
  PNG/SVG/PDF, печать листов 2×3 / 3×4, переназначение, история привязок), лента отзывов
  с фильтрами, настройки компании, привязка Telegram.
- **Обязательно:**
  - access-токен хранить в памяти, refresh — httpOnly cookie;
  - вызовы `/auth/refresh` **сериализовать**: при параллельном refresh срабатывает защита
    от повторного использования и сессия сбрасывается;
  - ошибка `legal_details_required` подсвечивает поля из `fields`;
  - предупреждение, если не заполнены реквизиты оператора ПД;
  - предупреждение, если `PUBLIC_BASE_URL` указывает на localhost;
  - раздел «Клиенты и согласия» для владельца: поиск по телефону и отзыв согласия.
- **Технологии:** React 19, TanStack Query, React Router, Tailwind 4, ECharts (своя обёртка,
  без устаревших react-обёрток). Запросы только через `src/api/` и хуки `src/hooks/`.
- Аккуратный современный дизайн, адаптивность под мобильные. Никаких Google Fonts и зарубежных CDN.

## 4. Открытые вопросы и бэклог

**Ждут решения владельца**
- Тексты согласий `backend/app/consents/*.txt.j2` должен проверить юрист перед продажей.

**Бэклог (вне MVP)**
- ML-анализ текстов (аспекты, тренды, дайджест).
- Биллинг и тарифы, админка владельцев сервиса, интеграции с CRM и онлайн-записью.
- Каналы уведомлений кроме Telegram (email, MAX, SMS) через `NotificationChannel`.
- Перевыпуск токена QR-точки (если визитка «утекла») с подтверждением.
- Переключатель компаний в UI (API уже поддерживает `X-Organization-Id`).
- Доступ мастера к своей визитке QR (сейчас решено не давать).
- Мониторинг и алерты инфраструктуры (только российские сервисы или self-hosted).

## 5. Запуск с нуля на новой машине (Windows, без make)

### 5.1. Установить

1. **Git for Windows** — <https://git-scm.com/download/win>.
2. **Docker Desktop** с бэкендом WSL 2 — <https://www.docker.com/products/docker-desktop/>.
   Запустите его и дождитесь статуса «Engine running».
3. По желанию, для IDE и запуска без Docker:
   - **uv**: `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`;
   - **Node.js 24 LTS**.

   Для работы через Docker они не нужны.
4. **Claude Code** — подхватит `CLAUDE.md` из корня репозитория.

### 5.2. Получить код

```powershell
git clone https://github.com/Arseniy0203/qr-reviews.git
cd qr-reviews
```

В `.gitattributes` задано `eol=lf`, поэтому shell-скрипты и конфиги останутся с LF даже на
Windows. `core.autocrlf` трогать не нужно.

### 5.3. Создать `.env`

```powershell
Copy-Item .env.example .env
```

Сгенерируйте три секрета и вставьте их в `.env` вместо значений `change-me-...`
(для dev можно оставить заглушки, но лучше сразу настоящие):

```powershell
# Каждый запуск печатает новый криптостойкий секрет (64 символа)
$b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
```

Подробнее о переменных — в разделе 6. Если порт 5432 занят (например, другим Postgres),
задайте `POSTGRES_HOST_PORT=5433`.

### 5.4. Поднять и наполнить

```powershell
docker compose up -d --build                       # первый раз несколько минут
docker compose ps                                  # все сервисы Up, postgres/redis healthy
docker compose exec backend alembic upgrade head   # схема БД
docker compose exec backend python -m scripts.seed # демо-салон «Лаванда», 300 отзывов
```

Seed печатает логины и ссылки на все QR-точки. Сразу после `up` бэкенд стартует около
10 секунд; если nginx отвечает 502, подождите.

### 5.5. Проверить

```powershell
docker compose exec backend pytest -q              # ~154 теста, ~40 с
docker compose exec backend ruff check .
docker compose exec backend ruff format --check .
docker compose exec bot pytest -q
docker compose exec frontend npm run build
```

- Кабинет (пока заглушка): <http://localhost:8080>
- Swagger: <http://localhost:8080/api/docs>. Логин через `POST /api/v1/auth/login`, затем
  кнопка **Authorize** с `access_token`.
- Форма отзыва: `http://localhost:8080/r/<token>` (токены печатает seed).
- Демо-входы: `owner@lavanda.demo`, `manager@lavanda.demo`, `anna@lavanda.demo`, пароль `demo12345`.
- С телефона в той же Wi-Fi: `http://<IPv4 компьютера>:8080/r/<token>`. Если не открывается,
  разрешите входящий TCP 8080 в брандмауэре (PowerShell от администратора):
  `New-NetFirewallRule -DisplayName "QR Reviews dev 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private`.
- Для сканирования QR телефоном временно задайте `PUBLIC_BASE_URL=http://<IPv4>:8080`
  и выполните `docker compose up -d backend`.

### 5.6. Подводные камни Windows

- В PowerShell 5.1 коммитьте через файл: `git commit -F msg.txt`. Иначе двойные кавычки
  внутри сообщения ломают аргументы.
- В Git Bash `docker run -v C:/...:/out` превращает `/out` в путь Windows. Используйте
  PowerShell или `MSYS_NO_PATHCONV=1`.
- `Invoke-RestMethod` показывает кириллицу кракозябрами: он читает JSON как Latin-1.
  С API всё в порядке, проверяйте через Swagger или браузер.

## 6. Переменные окружения

Полный список с комментариями — в `.env.example`.

**Получить у владельца** (его аккаунты, реквизиты и решения):

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | боевой бот (создаётся у @BotFather на аккаунт владельца). **Для разработки заведите своего тестового бота** и не используйте боевой |
| `PUBLIC_BASE_URL`, `DASHBOARD_BASE_URL`, `DOMAIN` | финальный домен прода. ⚠️ `PUBLIC_BASE_URL` зашивается в печатные QR |
| `LETSENCRYPT_EMAIL` | email для уведомлений Let's Encrypt |
| `PD_PROCESSOR_DETAILS` | реквизиты компании владельца сервиса (обработчик ПД), попадают в тексты согласий |
| `YANDEX_METRIKA_ID` | счётчик Метрики, если нужна аналитика |
| прод: `SECRET_KEY`, `HASH_SALT`, `INTERNAL_API_SECRET`, `POSTGRES_PASSWORD` | только если вы разворачиваете **существующий** прод. Смена `HASH_SALT` обнуляет антифрод-историю, смена `SECRET_KEY` разлогинивает всех |

**Сгенерировать самому** (dev, или новый прод с нуля):

| Переменная | Как |
|---|---|
| `SECRET_KEY`, `HASH_SALT`, `INTERNAL_API_SECRET` | команда из 5.3; в проде ≥ 32 символов и без префикса `change-me`, иначе бэкенд не стартует |
| `POSTGRES_PASSWORD` | любой длинный случайный пароль |
| `POSTGRES_HOST_PORT`, `REDIS_HOST_PORT` | порты на хосте, если стандартные заняты |

**Оставить по умолчанию для dev:** `APP_ENV=dev`, `COOKIE_SECURE=false` (в проде `true` обязательно),
`DEFAULT_TIMEZONE=Europe/Moscow`, все `AF_*` и `RATE_LIMIT_*`.
